## ١) الهدف

ربط حكاية بخدمات AI لتحويل التجربة من **رسوم مُعدّة مسبقًا** إلى مسار حي آمن:

1. شخصية كرتونية من صورة الطفل (بموافقة أهلية).
2. مشاهد فريدة لكل صفحة مع ثبات الوجه.
3. سرد عربي/إنجليزي مناسب للعمر.
4. تعليق صوتي عربي عالي الجودة.
5. فيديو كتيّب (صفحات + صوت) قبل أي توليد سينمائي ثقيل.

---

## ٢) المبادئ قبل أي تفعيل

1. **لا مفاتيح في المتصفح** — كل الاستدعاءات من الخادم (`/api/*`) فقط.
2. **موافقة ولي الأمر مسجّلة** قبل رفع أي صورة طفل.
3. **تقليل الاحتفاظ:** حذف/جدولة حذف الصورة المرجعية بعد اعتماد الشخصية.
4. **صدق التواصل:** التشابه كرتوني تقريبي وليس بصمة وجه.
5. **فلترة محتوى أطفال** على النص والصور قبل المعاينة للأهل.
6. **التكلفة تحت السيطرة:** طابور مهام + حدود توليد + كاش للشخصية الأساسية.

## ٤) الخيارات بالتفصيل

### ٤.١ توليد الصور والوجوه

#### أ) OpenAI Images (gpt-image)
- **مناسب لـ:** أسلوب قصصي صقل، برومبتات غنية، دمج مع نفس حساب OpenAI للنص/الصوت.
- **إيجابيات:** جودة عالية، توثيق جيد، مسار منتج واضح.
- **سلبيات:** تكلفة قد ترتفع مع كثرة صفحات الكتاب؛ سياسات صارمة لصور الأطفال يجب احترامها.
- **استخدام حكاية:** `character_base` ثم `scene_pages` مع تمرير مرجع الشخصية.

#### ب) Google Gemini Image / Imagen
- **مناسب لـ:** الحفاظ على الهوية من صورة مرجعية عبر مشاهد متعددة.
- **إيجابيات:** قوة مرجع بصري؛ إمكانية توحيد النص+الصورة عند Google.
- **سلبيات:** يحتاج ضبط صلاحيات وفاتورة Google Cloud/AI.
- **استخدام حكاية:** مرشّح قوي إذا كان ثبات الوجه عبر ١٢ صفحة هو الأهم.

#### ج) Flux عبر fal.ai أو Replicate
- **مناسب لـ:** تجارب سريعة، A/B للجودة مقابل السعر.
- **إيجابيات:** مرونة نماذج، تسعير تجارب غالبًا أخف.
- **سلبيات:** تفاوت الجودة؛ يحتاج طبقة توحيد برومبتات ومعايير قبول.
- **استخدام حكاية:** مسار تجريبي موازٍ قبل تثبيت المزوّد الإنتاجي.

#### د) Ideogram
- **مناسب لـ:** تجارب يكون فيها النص جزءًا من المشهد.
- **ملاحظة لحكاية:** النص العربي داخل الصورة حاليًا يُرسم عبر Canvas (`book-paint.js`)؛ Ideogram اختياري وليس أساسيًا.

### ٤.٢ توليد السرد

#### OpenAI GPT
- قوالب JSON للصفحات، تكيّف جندري، لغتان.
- سهل الربط إن كان حساب الصور/الصوت عند OpenAI.

#### Anthropic Claude
- ممتاز للحذر العمري والصياغة الأدبية الهادئة للأطفال.
- مرشّح قوي لمحرّك السرد حتى لو كانت الصور عند مزوّد آخر.

#### Google Gemini
- خيار توحيد النص+الصورة؛ جيد إن اختيرت Gemini للرسوم.

**قاعدة المحتوى الإلزامية (أي مزوّد):**
```text
بداية → حوار → لغز/عقدة → محاولة → حل → قيمة عمرية
بدون عنف حقيقي · بدون رعب · بدون تنمّر · تمييز واضح إن كانت قراءة تاريخية
```

### ٤.٣ الصوت (TTS)

| المزوّد | الجودة العربية المتوقعة | التكامل | توصية |
| --- | --- | --- | --- |
| ElevenLabs | عالية جدًا / عاطفية | API مباشر | **أساسي للقراءة السينمائية** |
| OpenAI TTS | جيدة وسهلة | نفس منظومة OpenAI | بديل اقتصادي |
| Azure Speech / Google TTS | مستقرة مؤسسيًا | سحابة أكبر | مناسب للمؤسسات لاحقًا |

**متطلبات حكاية:**
- لغة الصوت = لغة القصة (لا سقوط ل英语 مع نص عربي).
- قاموس نطق لأسماء الأطفال (عيسى، مدرك، صمود، أسماء مخصّصة).
- تقسيم الجمل صفحة بصفحة كما في `story-voice.js`.

### ٤.٤ الفيديو

#### المرحلة أ (موصى بها أولًا)
- صفحات الكتاب المعتمدة + مسار صوتي TTS.
- تجميع MP4 عبر FFmpeg في وظيفة خلفية.
- يغطي منتج «الحكاية السينمائية» بدون تكلفة Runway.

#### المرحلة ب (لاحقة)
- Runway / Kling / Luma لمشاهد حركة قصيرة مختارة (غلاف أو ذروة القصة فقط).
- لا تولّد كل الصفحات فيديو توليديًا في البداية (التكلفة والمخاطر مرتفعة).

## ٥) المعمارية المقترحة للربط

```text
[واجهة حكاية]
      │  رفع صورة + موافقة
      ▼
[POST /api/ai/jobs]
      │
      ├─ character_base  → Image provider
      ├─ scene_pages     → Image provider (+ character ref)
      ├─ story_draft     → Text provider (template + safety)
      ├─ tts             → ElevenLabs / OpenAI TTS
      └─ video           → FFmpeg worker (pages + audio)
      │
      ▼
[ai_jobs في Postgres] → حالة queued/processing/ready/failed
      │
      ▼
[معاينة أهلية] → اعتماد → أصول نهائية للطلب/التصدير
```

العقود موجودة في: [`platform/api-contracts.md`](../platform/api-contracts.md)  
الجدول: `ai_jobs` داخل [`platform/schema.sql`](../platform/schema.sql)

## ٨) خطة التفعيل على مراحل (بدون تنفيذ الآن)

### المرحلة AI-0 — اعتماد وتجربة مغلقة
- إنشاء حسابات المزوّدين وحدود إنفاق.
- اختبار جودة الوجه على عيّنة داخلية.
- تثبيت البرومبتات في ملفات منفصلة (مثل أسلوب `family-art-prompts.md`).
- كتابة سياسة: ماذا يُحفظ؟ كم مدة؟ متى يُحذف؟

### المرحلة AI-1 — شخصية أساسية فقط
- `character_base` من صورة + موافقة.
- معاينة الأهل قبل أي قصة كاملة.
- لا مشاهد متعددة بعد.

### المرحلة AI-2 — مشاهد الصفحات
- توليد صفحات مرتبطة بالقصة المعتمدة.
- إعادة استخدام الشخصية الأساسية كمرجع ثابت.
- رفض التسليم إن فشلت صفحة أو انخفضت الدقة عن الحد.

### المرحلة AI-3 — سرد مُولَّد مقيَّد
- قالب JSON للصفحات + تكيّف جندري.
- فلتر سلامة؛ مراجعة بشرية اختيارية للطباعة المدفوعة.

### المرحلة AI-4 — صوت ثم فيديو
- TTS لكل صفحة.
- تجميع MP4 وتسليمه بعد الدفع.

## ٩) معايير قبول الجودة

| المقياس | الحد الأدنى المقترح |
| --- | --- |
| تشابه كرتوني مقبول للأهل | متوسط تقييم داخلي ≥ 8/10 |
| ثبات الوجه عبر صفحات القصة الواحدة | متسق بصريًا دون اختلاط هوية |
| سلامة النص | 0 مخالفات عمرية في عيّنة الاختبار |
| لغة الصوت | مطابقة للغة القصة 100% |
| دقة مصدر الصفحة للطباعة المدفوعة | أصل كافٍ (مستهدف ≥ 4K) لا تكبير فارغ |
| زمن مهمة الشخصية الأساسية | هدف داخلي يُضبط بعد القياس (مثلًا < 2 د) |

## ١٠) التكلفة والمخاطر

### التكلفة
- أغلى عنصر غالبًا: **عدد صور الصفحات** (قصة ١٢ صفحة = ١٢ توليدًا + الشخصية).
- التخفيف: توليد الشخصية مرة واحدة، إعادة توليد صفحة فاشلة فقط، خطط تسعير تغطي هامش AI، كاش.

### المخاطر
| الخطر | التخفيف |
| --- | --- |
| توقعات مطابقة فوتوغرافية | نص واجهة صريح + معاينة قبل الدفع |
| سياسات مزوّد حول صور القاصرين | مراجعة شروط المزوّد؛ موافقة؛ تقليل البيانات |
| تكلفة مفاجئة | حد يومي للحساب؛ سقف توليد؛ مراقبة فاتورة |
| محتوى غير مناسب | قالب + فلتر + إيقاف تلقائي عند الشك |
| تباين جودة النماذج | اختبار A/B وتثبيت مزوّد إنتاجي واحد للصور |

## ١١) ما لن يُفعّل في هذه الوثيقة

- لا إضافة مفاتيح حقيقية.
- لا استدعاءات AI من الواجهة.
- لا تغيير لسلوك الإنتاج الحالي (الرسوم المُعدّة مسبقًا تبقى كما هي حتى AI-1).

الوضع الحالي للمنتج يبقى صادقًا في `/status` و`/api/health`: الذكاء الاصطناعي الحي **غير مفعّل**.

## ١٣) الخلاصة

**أفضل مسار لحكاية:**  
صور (OpenAI أو Gemini) + نص (Claude أو GPT) + صوت (ElevenLabs) + فيديو داخلي من الصفحات والصوت.

هذه الوثيقة هي مرجع الاعتماد والتنفيذ اللاحق؛ التفعيل يتم على مراحل AI-0 → AI-4 بعد تجهيز الحسابات والمفاتيح وسياسة الخصوصية التشغيلية.
